# Nextbell

АНУ-ын ~3000 хувьцааны (Russell 3000) маргаашийн чиглэлийг (өсөх магадлал) тооцоолж, үр дүнг **хараагүй өдрүүд дээр шударгаар дүгнэж** харуулдаг вэб.

> Анхаар: хувьцааны маргаашийн чиглэлийг 90%+ нарийвчлалтай таамаглах бодит арга байхгүй. Бодит түвшин ихэвчлэн 50–55%. Вэб нь хэмжсэн жинхэнэ нарийвчлалыг алдааны хязгаартай нь харуулна. Санхүүгийн зөвлөгөө биш.

## Хавтас

```
pipeline/   Python: өгөгдөл татах, загвар сургах, дүгнэх
web/        index.html (data/predictions.js-ийг pipeline бичнэ)
.github/    өдөр бүрийн автомат шинэчлэлт (GitHub Actions)
```

## Ажиллуулах (өөрийн компьютер дээр, интернэттэй)

```bash
cd pipeline
pip install -r requirements.txt

python 01_universe.py        # Russell 3000 жагсаалт (iShares), амжилтгүй бол S&P 1500
python 02_download.py        # Yahoo Finance-аас 6 жилийн өдрийн үнэ (10–25 мин)
python 03_train_predict.py   # backtest + маргаашийн таамаг (15–30 мин)
```

Эсвэл нэг командаар: `python run_all.py` (хурдан хувилбар: `python run_all.py --fast`).

Дараа нь `web/index.html`-ийг браузер дээр нээнэ. Өдөр бүр шинэчлэхийн тулд доорх «Өдөр бүр автоматаар шинэчлэх» хэсгийг үз.

## Өдөр бүр автоматаар шинэчлэх

### A. GitHub дээр (санал болгох: компьютер унтраастай ч ажиллана, үнэгүй)

GitHub Actions Даваа–Баасан бүр **Улаанбаатарын 06:30-д** (АНУ-ын зах зээл хаагдсаны дараа) өгөгдлийг шинэчилж, загварыг дахин сургаад, вэбийг GitHub Pages дээр шинэчилнэ.

1. github.com дээр шинэ repository үүсгэнэ: нэр `nextbell`, **Public** (үнэгүй Pages зөвхөн public repo дээр ажиллана; repo-д зөвхөн код байгаа, нууц зүйл байхгүй).
2. Энэ хавтсын бүх файлыг (`.github` хавтас, `pipeline`, `web` зэрэг) repo руу оруулна: *Add file → Upload files*. Хэрэв `.github` хавтас орохгүй бол (нууц хавтас тул заримдаа алгасагддаг): *Add file → Create new file*, нэрэнд `.github/workflows/daily.yml` гэж бичээд `github-workflow-daily.yml` файлын агуулгыг буулгана.
3. Repo → **Settings → Pages → Build and deployment → Source: GitHub Actions** гэж сонгоно.
4. Repo → **Actions** → «Nextbell daily update» → **Run workflow**. Эхний удаа бүх түүхийг татаж, backtest хийх тул 1–1.5 цаг болно. Дараагийн өдрүүд хэдхэн минут (шинэ өдрийг л татна).
5. Дууссаны дараа хаяг: `https://<таны-github-нэр>.github.io/nextbell/`

Мэдэх зүйл:
- Backtest (хараагүй өдрүүд дээрх нарийвчлал) удаан тул долоо хоног тутамд нэг л дахин бодно; өдөр бүр таамаг (маргаашийн магадлал) шинэчлэгдэнэ. Вэбийн доод хэсэгт «Backtest-ийг сүүлд бодсон» огноо харагдана.
- Yahoo заримдаа GitHub-ын серверийг хязгаарладаг. Тэгвэл тухайн өдрийн ажил алдаа заагаад зогсч, **вэб өмнөх өдрийн өгөгдлөөрөө үлдэнэ** (хагас дутуу өгөгдлөөр дарж бичихгүй), GitHub имэйлээр мэдэгдэнэ. Дараагийн өдөр өөрөө дахин оролдоно.
- Repo-д 60 хоног ямар ч өөрчлөлт ороогүй бол GitHub хуваарьт ажлыг зогсоодог. Зогссон бол Actions хэсгээс «Enable workflow» дарна.
- Түүх дахин бүрэн татмаар бол *Run workflow* дарахдаа `full_refresh`-ийг чагтална.

### B. Өөрийн компьютер дээр

Компьютер заасан цагт асаалттай, интернэттэй байх ёстой.

- **Windows** (Task Scheduler): командын мөрөнд нэг удаа (Улаанбаатарын цагаар Мягмар–Бямба 07:30: АНУ-ын Даваа–Баасан гарагийн хаалтын дараа):
  `schtasks /Create /SC WEEKLY /D TUE,WED,THU,FRI,SAT /ST 07:30 /TN Nextbell /TR "C:\зам\nextbell\run_daily.bat"`
- **Mac / Linux** (`crontab -e`): `30 7 * * 2-6 /зам/nextbell/run_daily.sh`

Үр дүн `web/data/predictions.js`-д бичигдэнэ, лог `data/daily.log`-д хадгалагдана. Эхний удаа `python pipeline/run_all.py` (бүтэн) ажиллуулсны дараа `--daily` горим ажиллана.

### Өдрийн горим яг юу хийдэг вэ

`python pipeline/run_all.py --daily`
1. Жагсаалт: шинэчилж чадахгүй бол өмнөх жагсаалтаа хадгална (3000 хувьцаа 1500 болж багасахгүй).
2. Үнэ: зөвхөн сүүлийн ~10 өдрийг татаад хуучин түүхтэй залгана. Split/dividend-ийн улмаас Yahoo хуучин үнийг дахин тохируулдаг тул хуучин түүхийг залгах цэг дээр харьцаагаар засна.
3. Хамгаалалт: хамгийн сүүлийн өдөр дээр хувьцааны 60%-иас бага нь л өгөгдөлтэй бол хадгалахгүй, алдаа заана.
4. Backtest: 7 хоногоос шинэ cache байвал дахин ашиглана, үгүй бол дахин бодно.
5. Эцсийн загвар шинэ өгөгдлөөр дахин сургагдаж, маргаашийн таамгийг гаргана.

## Загвар яг юу хийдэг вэ

- Хувьцаа бүрийн ~35 шинж чанар (өнгөрсөн өөрчлөлт, савалгаа, дундажаас хазайлт, RSI, арилжааны хэмжээ, зах зээлийн SPY/VIX), зөвхөн тухайн өдрийн хаалт хүртэлх мэдээллээр.
- Зорилт: маргааш хаалт өнөөдрөөс өндөр эсэх (1/0).
- Walk-forward backtest: загвар 63 өдөр тутамд зөвхөн тухайн үед байсан өгөгдлөөр дахин сургагдаж, дараагийн өдрүүдийг таамаглана. Бүх нарийвчлал зөвхөн эдгээр хараагүй өдрүүдээс гарна.
- Hyper-parameter-ийг test өдөр дээр тааруулдаггүй (урьдчилан тогтмол).
- Алдааны хязгаарыг хувьцаагаар биш өдрөөр тооцно (нэг өдөр хувьцаанууд хамт хөдөлдөг).
- Зах зээлийн ерөнхий чиглэлийг таамаглах боломжгүй гэж үзэж, өдөр бүрийн магадлалыг сүүлийн жилийн өссөн хувьцааны хувьд төвлөрүүлнэ.
- Харьцуулалт: зоос шидэлт (50%) ба «үргэлж өснө» гэсэн суурь таамаг.

## Хязгаарлалт (вэб дээр бас бичсэн)

- Өнөөгийн индексийн бүрэлдэхүүн дээр туршсан тул амьд үлдсэн компани руу хазайлт (survivorship bias) бий.
- Арилжааны шимтгэл, slippage ороогүй.
- Цаасан дээрх жижиг давуу тал бодит арилжаанд алга болж болно.

## Pipeline зөв ажиллаж байгааг шалгах

```bash
python make_synthetic.py --signal 0    # хуурамч санамсаргүй үнэ, олдох зүйл байхгүй
python 03_train_predict.py --mode demo --min-train 252 --step 126 --window 504 --iters 80 --min-dv 1e5
```

Сигналгүй өгөгдөл дээр нарийвчлал суурьтай ойролцоо (≈50%) гарах ёстой. 90%-д ойрхон гарвал future-leak байна гэсэн үг. (Энэ туршилт `data/` хавтсыг дарж бичнэ, бодит өгөгдлөө хийхээсээ өмнө `NEXTBELL_ROOT=/tmp/test` гэж тохируулаарай.)
